# Project Documentation

## Objective
Ensure another developer or team member can understand, run, maintain and deploy the project.

## Required Documentation
Maintain:
- README
- Project overview
- Technology stack
- Installation
- Environment variables
- Development commands
- Build commands
- Deployment
- Architecture
- Database
- API
- Authentication
- Integrations
- Testing
- Troubleshooting

## Environment
Provide `.env.example` with placeholder names only. Never commit secrets.

## Integrations
Document:
- Provider
- Purpose
- Required credentials
- Configuration
- Webhook URLs
- Testing method
- Failure handling

## Change Documentation
Major feature changes should update relevant documentation.

## Rule
Documentation must describe the actual implementation, not an assumed architecture.
